# V3 대비 최종 수정 기록

## 내용과 전개

- 핵심 연구 질문과 실무적 확장 질문을 2장에서 구분했다. 운영자의 주제·제목 선택이라는 개인 맥락을 첫 두 장에 배치했다.
- 20장(V3 본문17+부록3)을 본문15장+별도 상세 부록으로 재편했다. 실제 채널·영상을 보여주는 도입과 사례를 추가하고, PB 가상 기획은 네 장에서 한 장으로 압축했다.
- 전체 태그 분포 뒤에 채널별 제작 비중 히트맵을 추가했다. 이어 제작 비중과 상위권 비중의 분모를 구분하고 같은 태그의 채널 차이로 좁힌다.
- 음식 태그 표본이 가장 큰 두 채널의 33%·13%를 핵심 사례로 선택했다. 전체 40셀과 선정 이유를 공개한다.
- ‘설명형 표현’이라는 넓은 명칭을 ‘이유·원리를 예고하는 다섯 단어’와 정확한 문자열 규칙으로 바꿨다. 실제 제목의 포함·미포함 예시를 먼저 보여준다.
- 23%·35%→채널별 차이→같은 경제·소비 집단의 33%·45%로 범위를 좁힌다. 제목에는 단어가 없지만 썸네일에는 있는 실제 사례를 통해 분석 한계를 보여준다.
- 결론은 주제 후보·취재할 질문·제목 A/B·추가 검증 후 유지/수정으로 연결한다. 새로운 조회수 예측이나 인과 주장은 추가하지 않았다.

## 데이터와 분석

- 원본 7열·1,680행, 기존 태그·특징·모형 결과를 유지했다. V3 전체 JSON과 동일함을 확인했다.
- 새로 추가한 분석은 채널별 주제 제작 비중, 기존 규칙의 독립 재계산, 반복 설명 제거 검토, 실제 사례 9개의 제목·설명 대조, 제목만 태그한 민감도다.
- 표본 검토는 영상 전체 시청이나 전수 의미 코딩이 아니다. 사전 태그의 국가명·다의어·홍보 잔여 문제를 공개했다.
- 수집일은 CSV에 있다고 가정하지 않고 수집 보고서와 provenance 1,680건으로 대조했다.

## 디자인과 이미지

- 기존 아이보리 막대 중심의 반복 틀을 네이비·라임의 뉴스 에디토리얼 화면으로 교체했다.
- 공식 프로필 5개, 실제 1280×720 썸네일 9개를 확보하고 영상 ID·채널·제목·응답·해상도·해시를 기록했다. AI로 실존 이미지를 대체하지 않았다.
- 썸네일 표지, 채널 소개, 편성 히트맵, 두 지표 비교, 큰 숫자, 실제 영상 사례, 요약·마무리로 레이아웃을 구분했다.
- 1920×1080 기준으로 재설계하고 1366×768에서도 확인했다. 한글 폰트를 로컬에 포함하고 정지 PDF·reduced-motion에서도 내용을 유지했다.

## QA 수정 루프

1. 첫 렌더에서 이미지의 고정 HTML 높이가 레이아웃을 밀고 긴 콜라주 제목이 그리드 폭을 넓히는 문제를 발견했다. 높이 자동 계산과 최소 폭을 수정했다.
2. 모바일 부록의 긴 해시가 가로 넘침을 일으켜 줄바꿈을 보강했다.
3. 7·8장의 하단 간격과 11장 SVG 기준선 레이블을 수정한 뒤 다시 렌더했다.
4. 숫자 주변 띄어쓰기, PB·클릭률 풀이, 긴 제목의 단어 줄바꿈을 보강했다.
5. 전 15장×두 발표 화면 크기의 경계 검사, 이미지·조작, 분석·HTML 재현, PDF 렌더 대조를 통과했다.
6. 기본 모드의 초기 애니메이션 지연을 확인한 뒤 투명도 효과를 제거하고 정지 상태 보장을 추가했다. 기본 모드·전체화면·노트·목차·키보드·스와이프를 다시 확인했다.

정확한 검증 범위는 [QA 기록](qa_report.md)과 [분류 표본 검토](analysis_review.md)에 있다. V1~V4는 덮어쓰지 않았다.


## V4 공개 QA에서 발견한 문제와 V5 보정

V4는 데스크톱 창 크기 조절과 데스크톱 조작 검사를 통과했지만, 실제 모바일 브라우저 모드에서 화면 확장을 확인했다. 390px 레이아웃의 clientWidth와 달리 innerWidth가 1560px로 커졌고, 이를 다시 슬라이드 배율 계산에 써 가로 넘침이 유지됐다. 데스크톱 창 크기 조절만으로는 잡지 못한 문제다.

V5는 배율 계산을 document.documentElement.clientWidth/clientHeight 기준으로 바꿨다. 실제 모바일 모드(is_mobile·has_touch)에서 세로390×844·가로844×390으로 전15장을 각각 확인했다. 30개 상태 모두 scrollWidth=clientWidth였고 슬라이드가 화면 안에 들어왔다. 원래390px 화면이390px로 유지되며 실제 터치 이동·노트도 통과했다. 데이터·통계·스토리·이미지·디자인은 V4와 같다.

이미 고정한 V4를 덮어쓰지 않고 V5로 보정했다. V4의 공개 QA 실패와 원인은 [V4 배포 기록](https://mschoooo.github.io/news-topic-views-2025/deployments/v4.json)에 남긴다. V4는 최종본이 아닌 중간 검증본이다.
