# V5 최종 수정 계획과 확정 구성

기준은 사용자가 제공한 FINAL_REVISION_GUIDE.md이다. 제작 전 세운 계획의 핵심은 유지하고, 아래에 실제 제작·검증한 구성을 정리한다. V1~V4는 수정하지 않는다.

## 유지한 질문과 자료

- 핵심 연구 질문: 방송사 뉴미디어 뉴스 채널에서 콘텐츠 주제에 따라 조회수는 어떻게 달라지는가?
- 실무적 확장 질문: 제목 표현과 상대 조회수 성과의 관계가 주제·채널에 따라 어떻게 달라지는가?
- 대상: 2025년 일반 영상 1,680편, 공식 5개 채널. 조회수는 2026-10-18 수집 당시 누적값이다.
- 새 대규모 수집 없이 원본 7열과 V3의 주제 사전·제목 규칙·기존 결과를 유지했다. 추가한 것은 채널별 주제 제작 비중과 분류 검토용 집계다.

## V3에서 바꿀 구조

V3의 일반적인 막대와 텍스트 반복을 실제 채널·영상과 연결한다. 주제 정의와 상위권 정의를 한 장으로 묶고, 전체 분포→채널 편성→성과 비교→실제 사례 순서로 좁힌다. 제목 범주의 정의를 결과보다 먼저 제시한다. 가상 PB 기획 네 장은 한 장으로 줄이고, 결론은 확인한 것·모르는 것·다음에 검증할 것을 구분한다. 전체 표는 별도 HTML 부록으로 분리한다.

## 실제 이미지와 디자인

공식 프로필 5개와 실제 썸네일 9개를 확보했다. 영상 ID는 CSV URL에서 파생하고, 기존 Firecrawl 원본의 videoId·channelId·title과 대조했다. 모두 HTTP 200이며 썸네일은 전부 1280×720이다. 상세 제목·URL·해상도·출처·SHA256은 [이미지 출처](image_sources.md)와 [JSON](image_sources.json)에 있다.

1920×1080을 기준으로 좌우 96px, 상하 64px의 그리드를 사용했다. Pretendard 한글 글꼴을 로컬에 포함하고 대체 글꼴을 지정했다. 네이비·밝은 회색·라임·오렌지의 대비와 채널별 고정 색을 사용했다. 제목은 대체로 67~103px, 핵심 숫자는 더 크게, 본문·차트는 27~43px 수준이다. 표지·채널 소개·히트맵·증거 차트·영상 사례·요약·마무리로 리듬을 바꾼다. 이미지는 자르거나 늘리지 않고 원래 비율을 유지한다.

키보드·전체화면·노트·목차·터치를 유지하고 reduced-motion을 존중한다. 애니메이션은 보조적인 등장 강조이며 정지 화면에도 모든 정보가 있다. 복잡한 전체 표는 별도 부록으로 제공한다.

## 분석 보완과 검토

723편 복수 태그·282편 태그 없음·422편 상위권을 재계산했다. 반복 안내 문구 제거와 핵심 실제 영상 9개의 제목·설명을 표본 검토했다. 음식 사례의 제목만 태그한 민감도도 공개했다. 국가명·다의어 등 사전의 한계를 기록하고 유리한 결과를 위해 규칙을 바꾸지 않았다. 제목만 분석했으므로 썸네일의 ‘이유’는 세지 않았다는 실제 반례를 본문에도 보여준다.

## QA 계획과 실제 수정

원자료와 분석을 별도 폴더에서 재현하고 기존 V3 결과·V1~V4 파일 해시를 확인했다. 전 15장을 1920×1080·1366×768에서 렌더링하고 직접 검수했다. 이미지의 높이와 그리드 최소 폭, 모바일 부록의 긴 해시, 7·8장 하단 간격, 11장 기준선 레이블을 수정한 뒤 재렌더했다. PDF 15페이지도 전부 렌더링해 화면과 대조했다. 실제 청중 실험 대신 초독 관점의 자체 검토를 명시한다. [QA 기록](qa_report.md)에 검증 범위와 결과를 기록한다.

V5 HTML·PDF·발표 노트·출처·코드·수정 기록을 함께 고정 보관한 뒤 GitHub Pages를 갱신하고 공개 URL에서도 다시 확인한다.


## V4 공개 QA에서 발견한 문제와 V5 보정

V4는 데스크톱 창 크기 조절과 데스크톱 조작 검사를 통과했지만, 실제 모바일 브라우저 모드에서 화면 확장을 확인했다. 390px 레이아웃의 clientWidth와 달리 innerWidth가 1560px로 커졌고, 이를 다시 슬라이드 배율 계산에 써 가로 넘침이 유지됐다. 데스크톱 창 크기 조절만으로는 잡지 못한 문제다.

V5는 배율 계산을 document.documentElement.clientWidth/clientHeight 기준으로 바꿨다. 실제 모바일 모드(is_mobile·has_touch)에서 세로390×844·가로844×390으로 전15장을 각각 확인했다. 30개 상태 모두 scrollWidth=clientWidth였고 슬라이드가 화면 안에 들어왔다. 원래390px 화면이390px로 유지되며 실제 터치 이동·노트도 통과했다. 데이터·통계·스토리·이미지·디자인은 V4와 같다.

이미 고정한 V4를 덮어쓰지 않고 V5로 보정했다. V4의 공개 QA 실패와 원인은 [V4 배포 기록](https://mschoooo.github.io/news-topic-views-2025/deployments/v4.json)에 남긴다. V4는 최종본이 아닌 중간 검증본이다.
